# 이음이 QA 고도화 운영 체계

> 어르신이 실제로 물을 질문을 기준으로, 반복 테스트로 정확도를 **증명 가능하게** 끌어올리는 운영 체계.
> 작성: 2026-10-02 · 담당: Play4(탐) · 대상: 운영 실무자 + 개발팀

---

## 1. 철학 — "공급(사이트 전체)"이 아니라 "수요(어르신 질문)"

| 방식 | 문제 | 채택 |
|---|---|---|
| 사이트 전체 다 학습 (공급 기준) | 어르신 안 물을 행정문서까지 → 노이즈·비용 낭비 | ✗ |
| **어르신 질문 기준 학습 (수요 기준)** | 필요한 것만 고도화 → 효율·품질·관리 용이 | ✓ |

**핵심 원리(도서관 구조):**
- 학습(크롤) = 책을 서가에 꽂기 → **일회성 비용**
- 대화(답변) = 질문에 맞는 책 몇 권만 꺼내기 → **매번, 관련분만(상한 있음)**
- 즉 **학습을 많이 해도 매 대화 토큰·속도는 거의 안 늘어난다.** 비용은 "일회성 크롤"에 집중.

---

## 2. 고도화 절차 (반복 루프)

```
① 질문 뱅크 (확률 높은 순)
      ↓
② 자동 테스트 (각 질문 → 이음이 답변)
      ↓
③ 매트릭스 기록 (질문 · 답변 · 출처 · 평가 · 회차)
      ↓
④ 진짜 구멍 식별  ← ⚠️ "똑똑한 평가"가 관건
      ↓
⑤ 인간 검토 → 보강(자료/프롬프트) + 가이드
      ↓
   다시 ① (회차 반복 → 정확도 상승 기록)
```

### 확장 전략 (폭과 깊이를 단계적으로)
1. **1단계 — 핵심 질문**: 어르신이 가장 자주 물을 질문부터 바닥까지 정확하게
2. **2단계 — 파생 질문**: 핵심에서 갈라지는 후속 질문 ("그럼 신청은?", "얼마예요?")
3. **3단계 — 폭 확장**: 확률 낮은 질문, 변두리 주제
4. **4단계 — 깊이 심화**: 세부 조건·예외까지

> 각 단계를 "충분히 정확해질 때까지" 반복한 뒤 다음 단계로. 폭과 깊이가 회차마다 넓어지고 깊어진다.

---

## 3. 기록 체계 (복불복 아닌 "증명")

### 3-1. QA 매트릭스 (회차별 CSV)
| 분류 | 질문 | 출처(참조 서비스) | 평가 | 답변 요약 | 회차 | 일시 |
|---|---|---|---|---|---|---|

- 매 테스트 회차마다 저장 → **정확도 추이**가 남음
- 실무자가 "어느 질문에 어떻게 답했고, 무엇을 근거로 했는지" 한눈에

### 3-2. 정확도 로그 (회차 추이)
```
1회차: 36질문 · 97% · 구멍 1 (기초연금 금액)
2회차: 70질문 · 94% · 구멍 4  ...
3회차: ...
```
→ "수십·수백 회 테스트로 고도화됨"이 **데이터로 증명**된다. 테스트가 복불복이 아님.

---

## 4. 평가 방법 — 고도화의 진짜 관건

**교훈(1회차):** 단순 키워드 평가는 "되묻기·정직한 안내"를 구멍으로 **오판**한다.
- 1회차: 키워드 평가 → 69%(구멍 11) 로 잘못 보임
- 정교 평가 → **실제 97%**(구멍 1)

**따라서 평가는 다음 중 하나로:**
| 방법 | 장점 | 비용 |
|---|---|---|
| **LLM 평가** (답변을 AI가 "충실/구멍" 판정) | 오판 적음, 자동 | 약간의 토큰 |
| **담당자 검토** (매트릭스 직접 확인) | 가장 정확 | 사람 시간 |
| 혼합 (LLM 1차 → 사람 최종) | 균형 | 중간 |

---

## 5. 인간 피드백 반영 루프

```
담당자가 매트릭스 검토
   → "이 답변은 약하다/틀렸다" 체크 + 방향 메모
   → 보강 지시 (자료 추가 / 링크 깊이 / 프롬프트 규칙)
   → 재학습(sync) 또는 프롬프트 수정
   → 재테스트 → 매트릭스에 개선 기록
```

- 피드백은 **구조화**: [질문 · 현재답변 · 문제 · 바라는답변 · 조치]
- 조치 유형: ①자료 보강(sync) ②링크 깊이 조정 ③프롬프트 규칙 ④서비스 추가

## 6. 대시보드 (실무자용) — 설계 제안

> 목적: **제품 정확도를 증명**하고, 실무자가 구멍을 보고 보강 방향을 잡게.

### 화면 구성(안)
1. **정확도 요약**: 전체 성공률 · 분류별 성공률 · 회차 추이 그래프
2. **구멍 리스트**: ❌/△ 질문 + 답변 + 출처 + "보강 필요" 태그
3. **질문 뱅크 관리**: 질문 추가/수정, 확률(우선순위) 지정
4. **보강 이력**: 언제 무엇을 보강했고 정확도가 얼마나 올랐는지
5. **서비스별 학습 상태**: chunk 수 · 이미지 판독 · 깊이 설정(얕음/보통/깊음)
6. **증명 배지**: "누적 N회 테스트 · 현재 정확도 97%"

### 구현 방식(안)
- QA 매트릭스 CSV/DB를 읽어 표·그래프로 렌더
- 기존 관리자 대시보드(서초-이음이-관리자-대시보드.html)에 **탭 추가** 또는 별도 페이지
- 1차는 정적 리포트(자동 생성) → 2차는 실무자 입력(피드백) 반영

## 7. 현황 (2026-10-02, 1회차)

- **질문 36개 테스트 → 정확도 97% (35/36)**
- 분류별: 건강 10/10 · 생활 10/10 · 일자리 8/8 · 복지 7/8
- 진짜 구멍 1개: **"기초연금 얼마나 나와요?"** (금액 정보 없음)
- 산출물: `이음이_QA매트릭스_1회차.csv`
- 비고: 되묻기·전화번호 안내·기관 연결은 정상 작동. facts 슬림화(비용 70%↓) 후에도 품질 유지.

## 부록 — 운영 원칙
- **학습 비용 = 일회성 크롤**, 대화 비용은 거의 불변(관련분만 꺼냄)
- **깊이는 서비스별 선택**(얕음 2 / 보통 8 / 깊음 15) — 중요한 곳만 깊게
- **"무한정 전부"보다 "넉넉히 깊게"** — 노이즈 방지
- **평가가 똑똑해야** 진짜 구멍이 보인다 (단순 키워드 금지)
